# CINS Content Standards

These rules keep the guide navigable as more students contribute. They are intentionally simple: every page has one job, and every external resource has one canonical entry.

## 1. Page responsibilities

| Page | Its responsibility | Do not use it for |
|---|---|---|
| **Start Here** | Point visitors to the right part of the guide. | Repeating the curriculum, AI instructions, installation notes, or full safety policy. |
| **Curriculum** | Define the CINS stage structure, sequence, scope, and publication status. | Repeating stage lessons or copying resource descriptions. |
| **Stage pages** | Explain the topics and learner guidance for that stage. | Repeating the entire curriculum map or listing every external resource. |
| **Learning Resources** | Catalogue external learning material by subject. | Creating a second global curriculum or duplicating the same provider in multiple pages. |
| **Tool Library** | Explain individual tools and their legitimate uses. | Replacing the curriculum or acting as a list of required installations. |
| **Club Hub** | Maintain governance, contribution, safety, and quality rules. | Repeating beginner learning instructions. |

## 2. One canonical resource entry

Every course, website, video channel, documentation project, lab platform, or community should have **one full entry** in its primary subject page.

When a resource is useful in another subject:
- Do not copy its description into the second page.
- Add a short internal link to the canonical entry or its subject page.
- If one platform contains several distinct courses, each course may have its own entry when the official pages and learning outcomes are genuinely different.

Use the official project or provider URL as the identity for deduplication. Avoid listing the same destination under different names.

## 3. Required CINS stage-fit label

Every resource entry must include a line called **CINS stage fit**.

Use one of these forms:
- **Stage 0 — Orientation**
- **Stage 1 — Computer Fundamentals**
- **Stage 1 — Parallel Python Track**
- **Stage 2 — Networking / Linux / Windows / Internet & Web**
- **After Stage 2 — Specialist learning**
- **Reference — Useful across stages**

For a resource that spans multiple stages, state which sections fit each stage and which sections should be deferred. Do not assign a stage that the published curriculum has not established. Use **After Stage 2 — specialist material; exact stage not yet assigned** when the later stage number is not settled.

The stage-fit label describes where the resource is useful in CINS. It does not mean CINS has completed, tested, or endorsed the provider's entire course.

## 4. Resource quality fields

Each entry should make it easy to understand:
- What the resource is and what it teaches.
- Its intended level and prerequisites.
- Its CINS stage fit.
- Whether it is free, freemium, or paid, with a current official access link.
- Whether an account, special hardware, or local environment is required.
- The official destination and documentation.
- What was actually checked and when.

Do not infer price, course content, prerequisites, or supported systems from third-party summaries when the provider's own page is available.

## 5. Review labels are not interchangeable

- **Link checked:** the destination opens and matches the named resource.
- **Content reviewed:** a contributor checked the description against the provider's current material.
- **Lab verified:** a contributor completed or independently checked the stated lab/setup in an authorized environment.
- **Needs review:** an update or concern requires attention.
- **Archived:** the resource is retained for context but is no longer recommended.

Never claim a course, lab, tool installation, or command has been tested when it has only been read about.

## 6. Internal consistency and presentation

Before submitting a change:
1. Search for the resource URL or title to avoid duplicates.
2. Confirm the page has one clear responsibility.
3. Check that the CINS stage-fit label agrees with the current curriculum.
4. Link to the canonical entry from related pages instead of copying it.
5. Check internal links and remove links to deleted pages.
6. Do not add a new global roadmap. The Curriculum page owns the progression.

Visual and interaction improvements are welcome when they make learning clearer, improve accessibility, or make the site easier to use. Keep the CINS identity recognisable and check:
- Both light and dark colour schemes.
- Mobile and narrow-screen layouts.
- Keyboard access and readable focus states for interactive elements.
- Colour contrast and meaningful text alternatives for diagrams.
- Reduced-motion preferences for animated elements.

Avoid decoration that competes with the lesson. A visualisation should explain a real concept, be technically accurate, and have a text explanation for readers who cannot or do not use the visual.
