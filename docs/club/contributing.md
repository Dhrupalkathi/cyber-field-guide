# Contributing to the Guide

You do not need to be an expert to help. Useful contributions include fixing a broken link, explaining a term in simpler language, suggesting a quality course, improving accessibility, or checking a technical description against official documentation.

## Before proposing a change

1. Search the guide for the resource title and official URL so you do not create a duplicate.
2. Choose the page that owns the subject. Every external resource should have one full entry in one primary location.
3. Use the [resource-entry template](../templates/resource-entry.md) for a new course, website, video channel, lab, or community.
4. Include its CINS stage fit. If it spans several stages, identify the relevant sections and what should be deferred.
5. Prefer official project, course, and documentation links. Do not guess installation commands, prices, prerequisites, or supported systems.
6. Keep examples safe and within systems or labs for which permission is explicit.

## How to propose a change on GitHub

1. Open the page you want to improve in the repository.
2. Select the pencil icon to edit the file.
3. Make a focused change and keep the existing page structure.
4. Choose **Create a new branch for this commit and start a pull request**.
5. Explain what changed and provide the sources you used.
6. Submit the pull request. A maintainer reviews it before it is merged.

You can contribute through the GitHub website; you do not need Kali Linux or a local development environment to edit Markdown pages.

## What reviewers look for

- Accuracy and traceable sources.
- Clear explanations suitable for the stated learner level.
- Honest difficulty, prerequisites, and access/cost notes.
- Correct CINS stage fit and no conflict with the Curriculum.
- One canonical resource entry, with internal links from related pages.
- Safe examples and explicit authorization boundaries.
- A review label that reflects what was actually checked.
- No secrets, private information, or copyrighted course material.

Please read the [Safety and Ethics Rules](safety-and-ethics.md) and [CINS Content Standards](content-standards.md) before contributing.
