# CINS Cybersecurity Learning Journey



This is the common starting point for a learner who may have **zero experience with cybersecurity, programming, Linux, or Kali Linux**.

The first two stages build understanding before specialist tooling. Learners are free to choose the topics they want to explore in more depth and may use AI as a tutor for examples, explanations, simulations, and guided learning.

## The first two stages

| Stage | Purpose | Main learning focus |
|---|---|---|
| **Stage 0 — Orientation and Cybersecurity Awareness** | Understand the field, ethics, safety, personal security, and career options. | Cybersecurity concepts, domains, authorization, safe learning environments, personal security, and careers. |
| **Stage 1 — Computer Fundamentals** | Understand computers, hardware, data, software, files, virtualisation, and troubleshooting concepts. | How a computer works, how data is represented, how software runs, and how to reason about technical problems. |
| **Parallel track — Python** | Begin computational thinking and programming alongside Stage 1. | Python fundamentals, reading code, debugging, and understanding program behavior. |

## AI-guided self-directed learning

At the beginning of each stage, learners are invited to use an AI assistant to explore any topic they choose. Ask for examples, explanations, fictional scenarios, code walkthroughs, diagrams, interactive questions, or a guided simulation that matches your current knowledge.

AI output is a learning aid, not an authority. Check important information against official documentation and reliable sources. Follow the safety boundaries in the curriculum and never share passwords, tokens, private records, or confidential data with AI tools.

After understanding and verifying what you have learned, you may create your own original notes, diagrams, explanations, or resource pages and submit them to the repository. A human review for accuracy, safety, privacy, and source attribution is required before publication. Do not publish raw or unverified AI-generated material.

## Fixed sequencing decisions

These are intentional curriculum rules, not optional tool preferences:

1. **Stage 0 comes first.** Students learn what cybersecurity includes, why authorization matters, and how to learn safely before using security tools.
2. **Stage 1 teaches computer fundamentals.** Students build a mental model of components, data, software, and program execution.
3. **Python begins in Stage 1.** Programming is a parallel skill track, not a prerequisite stage that delays cybersecurity learning.
4. **Networking comes before Linux.** This is the agreed order for Stage 2. Linux administration, Windows administration, and detailed networking are not Stage 0/1 requirements.
5. **No Kali Linux requirement.** A browser and an ordinary computer are sufficient for Stage 0 and most Stage 1 learning. No high-end hardware, paid software, or local virtual-machine lab is required.
6. **Learner-directed exploration.** There are no fixed practical assignments or graded assessments in these stages. Learners choose which topics they want to explore further, with guidance from mentors and verified resources.
7. **Safety is non-negotiable.** Students use only systems, accounts, data, and labs they own or are explicitly authorized to use.

## What comes next?

Stage 2 is deliberately outside this draft. Its agreed order is:

**Networking → Linux → Windows → Internet and Web fundamentals**, while the Python track continues and adds skills when there is context to use them.

Later stages will introduce security tools, authorized security testing, defensive monitoring, incident response, and specialization paths. Do not pull those topics forward just because a popular platform places them earlier in one of its courses.

## How to use each module

Each module explains why a topic matters, what it covers, and what the learner should understand. Choose which topics you want to explore more deeply and use the AI-guided learning instructions at the start of the relevant stage.
