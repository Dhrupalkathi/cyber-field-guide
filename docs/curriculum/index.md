# CINS Cybersecurity Learning Journey

> **Status: Working curriculum draft v1.0 · Last resource review: 31 October 2026.**  
> This is the existing CINS Stage 0/Stage 1 curriculum, split into smaller website pages for navigation. Its scope and sequence are preserved. It is a working draft, not a claim of formal DAU/CINS approval.


This is the common starting point for a learner who may have **zero experience with cybersecurity, programming, Linux, or Kali Linux**.

The first two stages deliberately build understanding before specialist tooling. The curriculum is self-paced: students progress when they can demonstrate the learning outcomes, not because a fixed number of weeks has passed.

## The first two stages

| Stage | Purpose | What learners complete |
|---|---|---|
| **Stage 0 — Orientation and Cybersecurity Awareness** | Understand the field, ethics, safe practice, personal security, and career options. | A safe-practice agreement, a cybersecurity-domain map, and a private personal-security checklist. |
| **Stage 1 — Computer Fundamentals** | Understand computers, hardware, data, software, files, virtualisation, and basic troubleshooting. | A computer-fundamentals notebook, practical activities, and a troubleshooting record. |
| **Parallel track — Python** | Begin computational thinking and programming alongside Stage 1. | Small original programs, tested and explained by the learner, ending in a Cyber Fundamentals Quiz. |

## Fixed sequencing decisions

These are intentional curriculum rules, not optional tool preferences:

1. **Stage 0 comes first.** Students learn what cybersecurity includes, why authorization matters, and how to practise safely before being taught security tools.
2. **Stage 1 teaches computer fundamentals.** Students build a mental model of components, data, software, and program execution.
3. **Python begins in Stage 1.** Programming is a parallel skill track, not a prerequisite stage that delays cybersecurity learning.
4. **Networking comes before Linux.** This is the agreed order for Stage 2. Linux administration, Windows administration, and detailed networking practice are not Stage 0/1 requirements.
5. **No Kali Linux requirement.** A browser and an ordinary computer are sufficient for Stage 0 and most Stage 1 work. No high-end hardware, paid software, or local virtual-machine lab is required.
6. **Progress is evidence-based.** A learner should explain concepts, complete practice, pass checkpoints, and document their work.
7. **Safety is non-negotiable.** Students use only systems, accounts, data, and labs they own or are explicitly authorized to use.

## What comes next?

Stage 2 is deliberately outside this draft. Its agreed order is:

**Networking → Linux → Windows → Internet and Web fundamentals**, while the Python track continues and adds skills when there is context to use them.

Later stages will introduce security tools, authorized testing, defensive monitoring, incident response, and specialization paths. Do not pull those topics forward just because a popular platform places them earlier in one of its courses.

## How to use each module

Each module contains a reason for learning it, the topics to cover, observable learning outcomes, a practice activity, and a checkpoint. Mentors may use different teaching materials if they meet the same outcomes.

A student may move faster through concepts they already understand, but should still demonstrate the relevant outcome. A certificate or completion badge alone is not proof of practical understanding.
